## Purpose

定义 Admin UI 的响应式布局契约：最小支持视口宽度、控件密集的横向容器在放不下时应折行而非挤压文字、弹窗内多列表单在窄视口下降为单列、弹窗在视口高度不足时必须可滚动且操作区可达、不可断的长文本必须能换行。这些约束保证维护者在 375px 到超宽桌面之间的任何视口下都能读懂界面并点到每个操作。

## ADDED Requirements

### Requirement: 最小支持视口宽度为 375px

Admin UI SHALL 在视口宽度不小于 375px 时保证：页面无横向滚动条，且所有可见操作控件完整落在视口内可被点击。

窄于 375px 的视口不在支持范围内，MAY 出现横向滚动。

#### Scenario: 375px 下顶栏不溢出

- **WHEN** 视口宽度为 375px，打开 Admin UI 首页
- **THEN** 页面无横向滚动条，顶栏的模式切换、深色模式、刷新、对外 API、运行时设置、登出六个控件全部落在视口内且可点击

#### Scenario: 320px 不作保证

- **WHEN** 视口宽度为 320px
- **THEN** 允许出现横向滚动，本规范不对该宽度下的布局作断言

### Requirement: 控件密集的横向容器放不下时折行

同一横向容器内并列多个不可收缩控件时，容器 SHALL 在可用宽度不足时折行，MUST NOT 通过挤压容器内的文本元素来腾出空间。

容器高度 SHALL 允许随折行增长，MUST NOT 用固定高度截断折行后的内容。

判定标准是容器内的文本元素在任何受支持视口宽度下都保持其自然单行宽度，不被压缩到逐字竖排。

#### Scenario: 凭据管理标题行在桌面宽度下横排

- **WHEN** 视口宽度为 1440px，「凭据管理」区域右侧渲染全部控件
- **THEN** 「凭据管理」标题横向排列于单行，右侧控件折行显示，页面无横向滚动条

#### Scenario: 超宽视口同样横排

- **WHEN** 视口宽度为 1920px 或更宽
- **THEN** 「凭据管理」标题保持横排单行，不因容器宽度上限而被挤压

#### Scenario: 顶栏折行后高度增长

- **WHEN** 视口宽度不足以容纳顶栏全部控件于单行
- **THEN** 顶栏折行为多行并相应增高，所有控件可见可点，页面无横向滚动条

#### Scenario: 弹窗内并列的统计项折行

- **WHEN** 视口宽度为 375px，Kiro Account Manager 导入弹窗展示成功、profile、重复、失败、跳过五项统计
- **THEN** 五项按行折入下一行，每项文本保持完整，不出现项与项错位交叠

### Requirement: 批量操作与标题行全局操作分行

凭据列表的批量操作（批量验活、批量刷新 Token、恢复异常、批量删除、批量余额/订阅）SHALL 渲染在标题行之外独立的工具栏行内，MUST NOT 与标题行的全局操作（定时刷新、添加凭据、更多操作）混排在同一容器内折行交错。

选中状态的变化只允许影响工具栏行与标题行左组的已选徽标，MUST NOT 改变标题行右组的控件构成。

#### Scenario: 桌面宽度下全选后标题行单行

- **WHEN** 视口宽度不小于 1280px，全选当前页
- **THEN** 「凭据管理」标题行保持单行，批量操作出现在独立工具栏行内且单行排列，页面无横向滚动条

#### Scenario: 选中凭据后新增控件不进入标题行

- **WHEN** 已选中若干凭据
- **THEN** 批量验活、批量刷新 Token、恢复异常、批量删除四项出现在工具栏行内，标题行框线容器内不出现这四项

### Requirement: 低频操作收进溢出菜单

标题行的低频操作（Kiro Account Manager 导入、批量导入、在线授权、刷新全部模型、清除已禁用）SHALL 收纳在「更多操作」溢出菜单内，MUST NOT 以并列按钮形式占据标题行宽度。

菜单项 MUST 保留原有可用性判据：清除已禁用在无已禁用凭据时禁用，刷新全部模型在无凭据时禁用。

#### Scenario: 低频操作从标题行移入菜单

- **WHEN** 打开「更多操作」菜单
- **THEN** 五项低频操作全部出现在菜单内，标题行框线容器内不存在同名按钮

#### Scenario: 菜单项可用性判据不丢失

- **WHEN** 系统内无已禁用凭据时打开菜单
- **THEN** 「清除已禁用」项处于禁用态

### Requirement: 弹窗内多列表单在窄视口下降为单列

弹窗内用固定多列网格排布的表单项，SHALL 在列宽不足以容纳其标签文本的自然宽度时降为单列。

本要求只约束含文本标签的网格。列内仅含宽度自适应输入控件、不含文本节点的网格不在范围内。

#### Scenario: 超时参数网格在窄视口下单列

- **WHEN** 视口宽度为 375px，打开运行时设置并展开 WebSocket 超时参数
- **THEN** 各参数单列排布，标签文本单行完整显示，不被折成两行

### Requirement: 弹窗必须有高度上限且操作区可达

弹窗内容高度超过视口时，弹窗 SHALL 被限制在视口高度内，且 SHALL 提供滚动通路使标题与底部操作区可被滚动到并点击。

高度上限与滚动通路 MUST 同时生效。仅设置高度上限而不提供滚动通路是不可接受的，这会使内容相对视口下移、底部操作区比未设上限时更远。

弹窗 SHALL 在两侧保留横向留白，MUST NOT 在窄视口下贴满视口两边。

#### Scenario: 批量验活弹窗在矮视口内可操作

- **WHEN** 视口高度为 667px，选中 10 条以上凭据并打开批量验活弹窗
- **THEN** 弹窗标题与底部按钮区都在视口内或可通过滚动到达，且可点击

#### Scenario: 内层已有滚动区的弹窗不出现双滚动条

- **WHEN** 弹窗内部已有自带高度上限的滚动列表
- **THEN** 该弹窗只呈现一层滚动条，不出现外层与内层同时滚动

#### Scenario: 窄视口下弹窗保留留白

- **WHEN** 视口宽度为 375px 时打开任意弹窗
- **THEN** 弹窗左右两侧各保留可见留白，圆角可见

### Requirement: 不可断长文本必须能换行

展示错误信息、文件路径等可能含长不可断 token 的文本时，容器 SHALL 允许在 token 内部断行。

这类文本 MUST NOT 导致其所在的滚动容器出现横向滚动条。

#### Scenario: 批量验活的错误信息换行

- **WHEN** 批量验活结果中某条的错误信息包含一段长度超过容器宽度且无空格的字符串
- **THEN** 该字符串在容器内换行显示，结果列表不出现横向滚动条

#### Scenario: 导入结果的文件路径换行

- **WHEN** Kiro Account Manager 导入结果中的文件路径长度超过容器宽度
- **THEN** 路径在容器内换行显示，结果列表不出现横向滚动条

#### Scenario: 导入结果的失败原因换行

- **WHEN** Kiro Account Manager 导入结果中某条的失败原因包含一段长度超过容器宽度且无空格的字符串
- **THEN** 该字符串在容器内换行显示，结果列表不出现横向滚动条

### Requirement: 布局约束需有自动化回归护栏

上述布局约束 SHALL 有自动化测试守护。在测试环境不做布局计算的前提下，测试 MAY 以样式类断言作为判据，但 SHALL 覆盖每一项约束对应的具体位置。批量操作分行与溢出菜单收纳的约束以 DOM 归属断言为判据：批量按钮只出现在工具栏行内、低频入口只出现在菜单内，标题行框线容器内不得出现同名控件。

对于必须同时生效才有效的成对约束（弹窗高度上限与滚动通路），测试 SHALL 断言两者同时存在。

断言某个样式类不存在时，判据 SHALL 按空格切分后比对完整 token，MUST NOT 用子串包含或正则词边界匹配。这两种写法会把作为其他类后缀出现的同名片段判为命中。

#### Scenario: 折行约束被断言

- **WHEN** 移除「凭据管理」标题行或顶栏容器的折行能力
- **THEN** 相应测试失败

#### Scenario: 弹窗成对约束被断言

- **WHEN** 弹窗基础样式只保留高度上限而移除滚动通路
- **THEN** 相应测试失败

#### Scenario: 类不存在的断言不被同名后缀误判

- **WHEN** 某容器的固定高度类被替换为同名的最小高度类，实现正确
- **THEN** 相应测试通过，不因新类名包含旧类名而失败
